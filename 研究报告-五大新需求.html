0结论先行

✅ 铁路不需要付费 API——12306 官方公开接口免费可用（需带 cookie 模拟浏览器）；天气不需要 key（Open-Meteo 免费，平台已接入）；首页图标免费热链。唯一需要爬虫的是抖音/小红书内容（无官方 API）。

一句话：除内容爬取外，其余全部免费 API 或纯前端实现，外部费用 ≈ 0 元。

1需求一 · 首页展示抖音/小红书账号（@少于无）

首页放两个社交图标 + @少于无，点击跳主页。纯静态展示，不需要任何 API。

图标资源（已实测可用）

平台图标源实测

抖音https://api.iconify.design/simple-icons/tiktok.svg（同源音符图标）✅ 200

落地

  • 首页头部加社交图标 + 文字，<img> 直接热链 SVG，零依赖。
  • 图标加 referrerpolicy="no-referrer" + onerror 兜底，防部分 CDN 防盗链。
  • 链接指向账号主页 URL（需用户提供主页地址）。

2需求二 · 全国铁路信息同步 —— 需要 API 吗？

🔑 答案：不需要付费 API。12306 官方公开接口免费，App/网页同源，返回 JSON。
数据接口Key
余票/车次/时刻kyfw.12306.cn/otn/leftTicket/query无
车站代码表otn/resources/js/framework/station_name.js（可下载本地化，约800KB）无
车次时刻表otn/czxx/queryByTrainNo无

实测情况

接口能连但默认 302 → 需先访问 otn/leftTicket/init 取 cookie（curl -c/-b），带 cookie + Referer + UA 后正常查询。技术上完全可行。

架构建议

纯前端方案（起步）车站表本地化 → 前端匹配三字码 → 直接 fetch 12306。零服务器成本；但官方接口未开 CORS，浏览器直连受限。
轻后端方案（正式推荐）平台已有的薄代理层转发 12306 请求（带 cookie/Referer/UA），前端只展示。成本≈0。
第三方替代（可选）聚合数据 juhe（免费300次/日）、阿里云市场。仅当 12306 反爬升级不稳定再考虑。
体验增强表单加"到达城市"、车次卡片（时间/历时/余票）、车次+接驳完整方案落结果页。

风险

  • 12306 无 SLA、节假日限流 → 失败降级为"请到 12306 官方核实"+ 保留现有通用建议。
  • 站名歧义（"北京"多站）→ 用车站下拉而非自由输入。
  • 合规：只展示余票/时刻公共信息，不做抢票/代购，安全。

3需求三 · 每日 7 点定时更新

两类数据分开处理：

🌤️ 天气（纯 API）免费 平台已接 Open-Meteo（实时 current + 16 天 daily + 去年 archive），refreshWeather() 已就位。每日 07:00 定时触发即可，无需爬虫。
📰 攻略/视频/文章需爬虫 抖音/小红书无官方内容 API，只能爬。推荐 MediaCrawler（GitHub，Playwright 模拟浏览器、免逆向）。调度 APScheduler / crontab 0 7 * * *。

合规与风险（重要）

⚠️ 抖音/小红书条款禁止未授权抓取。个人小规模低频（≤1次/日、单账号）风险可控，但建议：控制频率、勿批量下载、勿商业分发、遵守 robots.txt、防封 Cookie。更稳妥替代：投稿/白名单人工维护精选链接（零风险），爬虫作增强。

4需求四 · 个性化建议（让每个选项"有意义"）

本轮代码核查发现：表单已有经验/负重/人数/预算/出发城市字段，规则引擎已做初步差异化，但——

⚠️ 预算字段完全没用（收集后未消费）；出发城市交通只分"郑州/其他"两档；无到达/离开交通方式、无"时间优先 vs 性价比优先"、无随日期/朝向动态的机位建议。

② 预算 → 整体花费评估 + 推荐酒店/交通

  • 建立价格库（本地 JSON，随爬取更新）：火车价（12306 实时）+ 成都→香格里拉专线拼车（约 ¥200-300）+ 返回交通；香格里拉镇/仁村民宿 vs 亚丁村酒店（国庆价已搜集）；门票/观光车/电瓶车、向导费、马帮（150-400 元/包）、气罐、餐饮。
  • 逻辑：预算 − 交通 − 门票 − 住宿 = 结余 → 判断可行；不够则建议改轻装/缩短天数/拼车/淡季。
  • 酒店按预算分档：经济 <¥150 / 舒适 ¥150-350 / 品质 ¥350+，结合位置推荐。

③ 新增选项：到达/离开交通方式 + 时间优先 vs 性价比优先

  • 到达：飞机（稻城亚丁机场 YDC，海拔4411m 世界最高，提示高反）/ 火车到成都转专线 / 自驾；离开反向。
  • 时间优先 → 最短总耗时（飞机/直达车）；性价比优先 → 最省方案（普快+拼车），显示节省金额与耗时差。

6建议落地顺序

  1. Phase 1（纯前端最快见效）：首页账号图标 ＋ 机位/预算/交通方式/时间性价比个性化 ＋ 车站本地化选车次。
  2. Phase 2（轻后端）：12306 代理层（解决 CORS，真正打通全国车次实时查询）。
  3. Phase 3（定时爬取）：MediaCrawler + 每日 07:00 调度，喂给价格库与攻略库。
  4. Phase 4（合规加固）：内容来源标注、频率控制、可选投稿/白名单替代。
